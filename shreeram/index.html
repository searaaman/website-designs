from issue to release

  1. step 1

    understand the problem

    Read the issue, the code it touches and how it is used today, before writing anything.

  2. step 2

    model the data

    Get the tables and rules right first, so the API and the screens have less to fix later.

  3. step 3

    build end to end

    API, screen and model calls together, in small pull requests that are easy to review.

  4. step 4

    test and ship

    Tests on the paths that matter, CI on every push, then deploy and watch it run.
